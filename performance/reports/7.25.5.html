Yuneta 7.25.5: faster where it runs every second, and every price named

7.25.5 is a correctness release: crash safety of the stores and the schemas, a hardened agent audit, a stricter message bus. This page shows what that did to speed, measured against 7.25.4 on the same machine, with the same benchmarks, the two releases run alternately. The hot paths got faster or stayed where they were. The few operations that got slower are listed with the reason, because each one buys a guarantee.

How it was measured

7.25.5 against 7.25.4. Each benchmark of 7.25.5 linked twice: with the 7.25.5 libraries, and with the 7.25.4 module (compiled with the 7.25.5 headers) put before them. The two binaries run alternated, with a sync and a pause before each run; mean +- standard deviation (median). Figures of scope "change" are an A/B of one commit alone; scratch benchmarks are not in the tree. Source: performance/c/README.md and CHANGELOG.md "Performance, against 7.25.4".

Absolute figures. The benchmarks of performance/c/ and the ctest binaries test_topic_pkey_integer, test_topic_pkey_integer_iterator2 and test_topic_pkey_integer_iterator5, built from the 7.25.5 tree, run at tag time in rounds (n per figure: 5, or 3 for perf_c_treedb and perf_auth_bff), with a sync and a 3 s pause before each run and no CPU pinning. The per-second benchmarks drop their first and last second. Absolute figures of one machine: compare them with each other and with the reports of the same machine.

Machine. 11th Gen Intel Core i7-11370H @ 3.30 GHz, 4 cores / 8 threads (up to 4.8 GHz), 31 GiB RAM, Samsung SSD 990 PRO 2TB (NVMe) (ext4), Linux 7.0.0-34-generic x86_64, Ubuntu 26.04.1 LTS, glibc 2.43, gcc 15.2.0. Acer Nitro AN517-53. A development machine, with other work running at times; the A/B runs are alternated for that reason.

Build. RelWithDebInfo (-O2 -g -DNDEBUG), gcc 15.2.0, fully static: yes, TLS: OpenSSL 3.6.3 (bundled, static); mbedTLS not built on this machine. CONFIG_DEBUG_TRACK_MEMORY is on (the .config of this machine): every allocation is tracked. A build without it does less work per allocation; that build was not measured here.

The benchmarks are in performance/c/; the raw figures of this page are in 7.25.5.json; every A/B, change by change, is in performance/c/README.md and in the CHANGELOG.
