Yuneta Simplified · performance report · 2026-10-24

Yuneta 7.27.10: a store that writes json text as it arrives

7.27.10 gives timeranger2 an append for a record that is already json text, tranger2_append_record_text(), and gobj-c a reader of the members of a json object from its text, json_scan_object_members(), with jansson's verdict and no node built. A writer of raw history that receives frames as text no longer parses each one whole to read three of its members and dumps it again to store it: db_tracks stores 2.2 times more frames per second on the same machine (24 700 -> 53 300), and on a Xeon E-2386G holds 20 000 records per second at 55% of one core. Against 7.27.7, the last release with a study, every one of the 41 figures stays inside its noise or gets faster: the appends of perf_timeranger2 are 1.6 to 2.9% faster. The study found, and the release fixes, a 1.6% loss of the json append that the split of the append had brought.

How it was measured

7.27.10 against 7.27.7. Written on 2026-10-24, before the tag. 7.27.10 is the C code of the release: the main tree at cfe8bdc14 plus a 3-line patch to timeranger2.c that this study asked for (append_content() takes the system_flag the append already read, instead of reading it again from the topic json); the patch is committed before the tag. It is measured against 7.27.7, the last release with a study. 7.27.8 and 7.27.9 changed .c files only in modules/c/modbus and modules/c/mbus, and no measured binary links either (nm: 0 symbols of them in every benchmark and ctest binary), so their measured code is 7.27.7's and they were not built. 7.27.7 and 7.27.10 each built from a git worktree, with the same .config and compiler; outputs_ext shared (linux-ext-libs 1.25 at both). In each tree only the kernel libraries, the modules, performance/c/ and the three ctest binaries were built; perf_timeranger2 has not changed since 7.27.7. The two binaries of each benchmark run in rotation, the order turned every round, with a sync and a 3 s pause before each run (1 s for the three ctest binaries and the read phase): 8 rounds; 24 for perf_tr_treedb, perf_timeranger2, the TCP and TLS echo and both event loop echoes; 48 for the append test (the test_topic_pkey_integer chain) and for the read phase; perf_rotatory 16. The append test first measured 7.27.10 without the patch: -0.87% appends/s (t = -2.6) and -1.18% with a live reader (t = -2.8) after 48 rounds. An attribution A/B of that test with only timeranger2.c changed (7.27.7's against cfe8bdc14's, 24 rounds) placed it in commit 8d7e2a85f (-1.6%, t = -3.2; with a reader -2.0%, t = -4.0); forcing append_content() inline did not change it, and passing the system_flag removed it (+0.07%, t = 0.1). Every benchmark that appends was then measured again, both sides, with the patch: those are the figures of this report. Mean +- standard deviation (median), t = the change over its standard error; |t| < 3 is noise. The treedb figures are CPU time of the process per operation.

Absolute figures. The absolute figures of 7.27.10 are its side of the A/B run: its C code (cfe8bdc14 plus the system_flag patch), built on 2026-10-23/24 on the machine of the earlier reports. The per-second benchmarks drop their first and last second; reads page by page are the FORWARD pass. The binary sizes are those of the yunos built from the same tree.
