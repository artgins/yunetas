Yuneta 7.27.5: retention, and what it costs a replica to read

7.27.5 gives timeranger2 retention: a store deletes the old files of a key and keeps the g_rowid of every row that stays, and its followers hear the purge. It shipped without this report; a review found that, and that the read path of a replica had not been measured. Both are done here, the day after the release, on the machine of the earlier reports, 7.27.4 against 7.27.5, the two run alternately. A replica pays about 1 us more for every iterator open and every page, purged or not: one stat() that notices a purge whose signal it missed. That is +19% on a page of one row, +8% on an open, and noise on a page of 100 rows; the master does not pay it. The appends, the opens of a store, the treedb and the network move inside their noise, or by the placement of code that does not run.

Prices paid on purpose

What got slower, how much, and what it buys. Three of them buy nothing: no code on their path changed, and they are said as measured.

A page of 1 row, as a replica

+18.9%
7.27.4
5.11 µs
7.27.5
6.08 µs

check_purge_before_read(): before every iterator open and every page, a replica stat()s the first md2 file of the key, to notice a purge of the master whose signal it did not hear (an overflow of its watch, a follower down while the master purged, a replica without a follower), before the read meets files that are gone. About 1 us per call on this machine, purged or not. With the check made to return at once, the same code reads at 7.27.4's speed (5.11 us): the check is all of it. Kept: skipping it while nothing seems missed leaves a window (a signal not yet read from the queue) in which a read opens a deleted file.

How it was measured

7.27.5 against 7.27.4. Written on 2026-10-22, the day after the release (7.27.5 shipped without a report; a review found it). 7.27.4 and 7.27.5 each built from a git worktree of its tag, with the same .config and compiler; outputs_ext shared (linux-ext-libs 1.24 at both tags). In each tree only the kernel libraries, the modules, performance/c/ and the three ctest binaries were built (the whole SDK in the 7.27.5 tree, for the binary sizes). The read phase of perf_timeranger2, added for this report, was compiled into both trees: it uses only the public API, which did not change. The two binaries of each benchmark run alternately, the order flipped every round, with a sync and a 3 s pause before each run (1 s for the three ctest binaries): 8 rounds, and 16 more for the four figures that came out of their noise after 8 (perf_tr_treedb, the TCP and TLS echo, the event loop echo with an append). The read path was measured apart: the read phase alone, 24 rounds, four binaries in rotation (7.27.4, 7.27.5, the main tree at 24da06bc8, and that tree with check_purge_before_read() made to return at once), a sync and a 1 s pause before each run. Mean +- standard deviation (median), t = the change over its standard error; |t| < 3 is noise. The treedb figures are CPU time of the process per operation.

Absolute figures. The absolute figures of 7.27.5 are its side of the A/B run: the code of the tag, built on 2026-10-22 from a worktree of the tag on the machine of the earlier reports. Not a tag-time run: the release was tagged on 2026-10-21 without one. The per-second benchmarks drop their first and last second; reads page by page are the FORWARD pass. The binary sizes are those of that build of the tag.

Machine. 11th Gen Intel Core i7-11370H @ 3.30 GHz, 4 cores / 8 threads (up to 4.8 GHz), 31 GiB RAM, Samsung SSD 990 PRO 2TB (NVMe) (ext4), Linux 7.0.0-38-generic x86_64, Ubuntu 26.04.1 LTS, glibc 2.43, gcc 15.2.0. Acer Nitro AN517-53. A development machine, with other work running at times; the A/B runs are alternated for that reason.

Build. RelWithDebInfo (-O2 -g -DNDEBUG), gcc 15.2.0, fully static: yes, TLS: OpenSSL 3.6.3 (bundled, static); mbedTLS not built on this machine. CONFIG_DEBUG_TRACK_MEMORY is on (the .config of this machine): every allocation is tracked. A build without it does less work per allocation; that build was not measured here.

The benchmarks are in performance/c/; the raw figures of this page are in 7.27.5.json; every A/B, change by change, is in performance/c/README.md and in the CHANGELOG.
