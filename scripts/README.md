# scripts

This directory has the auxiliary scripts of the Yuneta source tree.
[`yunetas-env.sh`](../yunetas-env.sh) adds this directory to `PATH`.
After you source it, you can run each script by its name from any
directory.

## What is here

| Script                  | Purpose                                                                  |
|-------------------------|--------------------------------------------------------------------------|
| `migratev6tov7.py`      | One-shot migration tool. It moves a v6 timeranger2 store to the v7 layout. It is for the upgrade window from v6 to v7. A new installation does not need it. |
| `verify_api_coverage.py`| Compares every `PUBLIC` C function of the kernel and of the modules that it maps against the documented API anchors in `docs/doc.yuneta.io`. It reports the MISSING and EXTRA symbols of each header. |
| `verify_js_api_coverage.py`| The JS half of `verify_api_coverage.py`, for the two submodule packages (`kernel/js/gobj-js`, `kernel/js/gobj-ui`). It reads every export and compares it against the `(js_<name>)=` anchors under `api/js/` and `api/gobj-ui/`. It reports MISSING (public, undocumented) and STALE (documented, gone) symbols. A symbol that only a deep import reaches is INDEX-ONLY, not a failure. The gate is the public surface of the package. For gobj-js, that is everything, because its barrel is `export *`. For gobj-ui, it is the named re-exports of `index.js`. `--write` regenerates `api/appendix_js_api_index.md` with every symbol, its signature, its module and a source link. That link is pinned to the own tag of the submodule, which the script reads from its `package.json`. The two packages have their own version line, and a link pinned to the SDK tag points at a tag that they do not have. Without `--write`, the script examines the committed index for drift. The script warns when a documented file (`src/`, `index.js`) is different in the working tree of the submodule and in its tag. In that case, the `#L` anchors point into the tag, and the prose describes something else. The test is deliberately not "is HEAD the tag". A commit of a lockfile or a README cannot move a line number, and a warning that everybody learns to ignore is worse than no warning. The exit code is 1 on any finding, so you can use the script in a pre-commit hook. `--repin` retags the hand-written pages under `api/js/` and `api/gobj-ui/` to the current submodule tags. It also recomputes each `#L` anchor from the symbol that its `(js_<name>)=` label names. It is the JS twin of `check_doc_line_refs.py --repin`. That script matches only `artgins/yunetas` links and skips these links. After any submodule bump, run `--repin`, then `--write`. |
| `check_ste.py`          | Reports the Simplified Technical English violations in the docs that a program can find: contractions, semicolons, the banned modals (`should`/`would`/`may`/`might`/`could`), British spellings, Latin abbreviations, perfect tenses, phrasal verbs and the usual filler. It reads markdown table cells. It skips the Untouchables: code fences, inline code, link targets, URLs, and double-quoted text, which is quoted material under rule 8.6. `--summary` gives one line per file. `--rule <id>` filters to one category. `--strict` adds the judgement calls. For example, a possessive is legal when correct, and "just" is filler in "just run it" but temporal in "just built". The exit code is 1 when the script reports anything, so you can use it in a pre-commit hook. A clean run is not compliance. The script is a spell-checker for the rules that need no judgement. |
| `check_test_ports.py`| Lists the fixed ports of the tests (`tests/c`, `performance/c`: urls, `*PORT*` defines, `"port"` keys, `htons()`) by test binary. The exit code is 1 in two cases. In the first case, two binaries use the same port: `ctest -j` runs them at the same time, and the second fails with *"bind() FAILED"*. In the second case, a port is inside the ephemeral range 32768-60999: the kernel gives those ports to any socket, so the bind fails by chance. The files of one binary can share a port (`main_<name>.c` with `c_<name>.c`, everything under `<test>/src/`). `--list` prints every port. |
| `check_test_databases.py`| Reports two tests that can use the same fixed directory at the same time (a timeranger2 store under `~/tests_yuneta`, a fixed `/tmp` path). `ctest -j` runs them at once, and they collide. Two such tests must share a `RESOURCE_LOCK` in their `CMakeLists.txt`. It needs a built `build/`. |
| `check_test_links.py`| Reports a build that links an archive of the SDK by a bare name. A bare name is a `-l` search, so the binary is not relinked when the archive changes and keeps the old library. |
| `check_md_fences.py`| Reports a fenced code block of a Markdown file that does not close. A closing fence with text after it does not close the block, and myst renders the text below it as code without a warning. |
| `api_index.py`| Writes `docs/doc.yuneta.io/api/appendix_api_index.md` from the headers: every public C function of the kernel, by header and A-Z. `--check` exits 1 when the file is not current. |
| `schema_diagram.mjs`| Writes the comment at the top of a `treedb_schema_<db>.c` (the graph of the schema) from its literal, with the code of the schema editor of gobj-ui. `--check` exits 1 when a comment is stale. |
| `check_doc_line_refs.py`| Audits the source references in the docs against the current tree, and turns them into links. The default mode reports which `file.c:NNNN` refs it can link with certainty. It also flags GitHub blob links pinned to a moving ref (`main`, a branch) and not to a release tag. This mode is a guard: it fails on a line out of bounds or on any unpinned link. `--linkify=<TAG>` turns the colon-form refs that it can verify into GitHub source links. These links are pinned to the release tag and point at the current definition of the function. `--strip-prose` removes the same unverifiable line numbers when they are written in prose (`(lines 316-335)`) or in comma form (`gobj.c, 3622`). `--link-symbols=<TAG>` makes the backticked symbols in narrative prose clickable. A function links to its doc entry when one exists, and else to the GitHub source. Gclasses and CLI tools link to their doc page. `--link-files=<TAG>` makes backticked bare file paths clickable (`kernel/.../c_yuno.c`, `glogger.c`, and shell scripts like `yunetas-env.sh`). It writes a file-level GitHub link with no line anchor, so the link never drifts. An abbreviated or relative path resolves by unique suffix against the canonical tree (no tests, no ESP32). A path in the wrong directory stays bare, to show the error. An absolute runtime path (`/yuneta/store/...`) stays bare, because it is not repo source. This is the only mode that indexes `.sh`. The audit and symbol modes read only C/H/JS/PY. `--link-jansson` links backticked jansson symbols (`json_pack`, `json_t`, …) to the jansson API reference (`apiref.html#c.<name>`). It leaves the `json_*` helpers of yuneta itself (for example `json_config`) to `--link-symbols`. `--link-api-source=<TAG>` links the heading (`## funcname()`) of every reference entry in api/ to its GitHub source. When a name has both a C and a JS definition, the "Source code:" files of the page select the correct one. `--prefer-doc-links` retargets the existing prose source links of documented functions to their doc entry (`#name`). As a result, the prose cites a documented function as prose → doc entry → source. `--repin=<NEWTAG>` is the pass for a release. It rewrites every `/blob/<anytag>/` to the new tag. It recomputes the `#L` anchor of each symbol link from the current definition of the symbol. It keeps the `[`fn`](…) at [file:line](…)` row twins in sync. File-level links get only the new tag. The script reports the symbols that disappeared, for a human to fix. The link modes are one-shot and idempotent: they skip anything that is already linked. Thus they do not move links to a new tag. When you tag a release, run `--repin`. |

## Adding new scripts

Put a new script in this directory. After the next
`source yunetas-env.sh`, the script is on `PATH`. Keep each script
self-contained, with no imports from other scripts. Give it a one-line
`--help`, so that new operators can find out what it does.

Nothing in this directory is part of the runtime. These scripts are
tools for developers and operators, not yunos.
