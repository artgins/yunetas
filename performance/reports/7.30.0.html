Yuneta 7.30.0: an HTTP stack no peer can stall, and what that costs

7.30.0 is a large release. HTTP gets a parser in linear time with limits, and a server that holds what a peer pipelines instead of cutting it; the auth BFF serves a session only to its Origin; a path that does not fit is never used cut; the date reader is rewritten by its rules. That has a price, and this page names it: on the HTTP path an HTTP round trip costs 0.7 us more (-5.1%) and a BFF login 6.8 us more (-8.2%); a date text in the local zone pays one stat() when TZ is unset; a conversion to a named zone pays seven system calls. The other 49 benchmarks, timeranger2, treedb, TCP, TLS, inter-yuno events and MQTT: 39 inside their noise, and the 10 that move, five each way, by 0.8 to 4.1%, run the same user instructions within 0.7%: where the code lies in the binary, not what it does.

Prices paid on purpose

What got slower, how much, and what it buys. These are the only figures slower because of a change.

A login through the auth BFF

+8.9%
7.29.3
13,116 logins/s
7.30.0
12,039 logins/s

+6.8 us per login: 76.2 to 83.1 us. Located with a profile of both builds: 3.1 us are named, the rest is spread with no function over 0.3 us. 1.4 us: C_PROT_HTTP_SR asks the transport for cur_tx_queue by name (gobj_has_attr() and gobj_read_integer_attr(), a strcmp walk), so that a peer that pipelines and does not read is held. 1.2 us: the head of each message in gbuffers, which is what makes it linear and limited. 0.5 us: the checks of the tokens and the form encoding of the request to the IdP (first_non_cookie_octet(), append_form_text()). What it buys: the BFF serves a session only to its Origin, a token outside cookie-octet is refused, and no request parameter reaches the IdP unencoded.

An HTTP round trip through C_PROT_HTTP_SR

+5.4%
7.29.3
75,918 round trips/s
7.30.0
72,012 round trips/s

+0.72 us per round trip: 13.2 to 13.9 us. 0.35 us: C_PROT_HTTP_SR asks the transport for cur_tx_queue by name at each request and each answer; it is what holds a pipeline instead of cutting it. 0.14 us: the head of the message in gbuffers, limited and linear (http.parse_request). The rest is spread. An application with a slow handler does not see it; it is the ceiling of a yuno that does nothing else but answer.

+145 ns per request of 10 headers, in one read: each header is stored once, when its value ends, in gbuffers with a limit. The same request in 16-byte pieces is 33% faster for the same reason.

A date text in the local zone, TZ unset

+578 ns: one stat() per text
7.29.3
167 ns
7.30.0
745 ns

One stat() of /etc/localtime per text that reads the local zone, about 0.5 us (470 ns here), and only with TZ unset: 167 to 745 ns for this text, the stat() and the tzset() around it. With TZ set the same text goes from 168 to 141 ns. It is the stat() a line of log pays in localtime(), and what lets a change of zone in the process, or of that file, be seen at the next text. 7.29.3 read this text in whatever zone libc held. TZ=:/etc/localtime takes it away, and with it the sight of a change of that file.

A conversion to a named zone

+2.08 us: 7 more system calls
7.29.3
1,951 ns
7.30.0
4,030 ns

Seven more system calls per call with a zone: 2 in 7.29.3 (the two stat() of tzset()), 9 in 7.30.0 (open, fstat, four pread and close of is_zone_file()). +2.08 us per call. It is what refuses a file that is not a zone, a FIFO that blocked the process in tzset(), and a TZif cut short. The call is for reports and range helpers, not for a data path.

How it was measured

7.30.0 against 7.29.3. Written on 2026-10-31, before the tag. 7.30.0 is the C code of main at 018feb9f1 (its benchmarks were built with the version already raised; the commit changes no .c file), measured against 7.29.3, the last release with a study, and no release sits between them. The change is 45 495 lines added and 4 068 removed in .c and .h over 7.29.3. The 7.29.3 side is a git worktree of the tag, its kernel, modules and benchmarks built by yunetas build --sdk-only with the same .config, compiler and outputs_ext (linux-ext-libs 1.28 in both). Every binary runs pinned to one CPU with taskset, which earlier studies did not do. The two binaries of each benchmark run in rotation, the order turned every round, a sync and a 3 s pause before each run (1 s for the three ctest binaries, which read the store the first one leaves): 10 rounds, none left out. Mean +- standard deviation (median), t = the change over its standard error; |t| < 3 is noise. The BFF figure and the event loop echoes are means of the samples of a run, the first left out (and the last, for the echoes). The treedb figures are CPU time of the process. The 47 figures of 7.29.3, and in this study also the raw event loop, the event loop with an append and MQTT, because the kernel changed under them. Two drivers written for this study are not in performance/c/ and link the libraries of each release: perf_http (150 000 HTTP round trips, one connection, C_IOGATE, C_CHANNEL, C_PROT_HTTP_SR and C_TCP, a raw C_TCP as the client, 5000 more as warm-up) and perf_micro (approxidate_careful(), gmtime2timezone(), ghttp_parser with no gobj, mask_secrets_in_text() and json_mask_secrets(); CPU time). With TZ set to the local zone, perf_micro ran 6 rounds more, and the header of 7.8 MB 3 rounds. Each figure outside its noise was explained with perf on the binaries of both sides, as root for the counters and with no setting of the machine changed: perf stat of user instructions, cycles, branch misses and L1 instruction-cache misses (5 alternated runs), and perf record of the CPU of the benchmark (3 runs). The system calls of a call with a zone were counted with strace. A figure is called placement when its binary runs the same user instructions and the cycles or the misses move.

Absolute figures. The absolute figures of 7.30.0 are its side of the A/B run, measured on 2026-10-31 on the machine of the earlier reports (kernel 7.0.0-42 now). The binary sizes are those of the yunos and the agent of the main tree, built with the same .config.

Machine. 11th Gen Intel Core i7-11370H @ 3.30 GHz, 4 cores / 8 threads (up to 4.8 GHz), 31 GiB RAM, Samsung SSD 990 PRO 2TB (NVMe) (ext4), Linux 7.0.0-42-generic x86_64, Ubuntu 26.04.1 LTS, glibc 2.43, gcc 15.2.0. Acer Nitro AN517-53. A development machine, at rest for this study: nothing else ran on it, and only the two agents of the machine stayed up.

Build. RelWithDebInfo (-O2 -g -DNDEBUG), gcc 15.2.0, fully static: yes, TLS: OpenSSL 3.6.5 (bundled, static: linux-ext-libs 1.28); mbedTLS not built on this machine. CONFIG_DEBUG_TRACK_MEMORY is on (the .config of this machine): every allocation is tracked. A build without it does less work per allocation; that build was not measured here.

The benchmarks are in performance/c/; the raw figures of this page are in 7.30.0.json; every A/B, change by change, is in performance/c/README.md and in the CHANGELOG.
